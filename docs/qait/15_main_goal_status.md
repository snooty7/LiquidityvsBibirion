# Main-goal status after broader validation

The objective remains an evidence-based, modular adaptive engine that can be compared objectively with the existing LiquidityvsBibirion strategies. The objective of improved risk-adjusted performance is **not established** by the current results.

| Area | Current evidence | Boundary |
|---|---|---|
| Repository/QAIT research | Architecture assessment, public claims classified, sources and access limitations recorded | Proprietary algorithms and performance remain unverified |
| Modular engine | Deterministic context, regime, structure, scoring, protection and exit decisions; explicit raw provenance | Disabled offline research engine; no adaptive live order route |
| Signal consistency | Anchored source identity, baseline ranked-map lifecycle, closed M5/M1 confirmation and causal fixed windows | Intersects existing candidates; no independently delayed adaptive entry stream |
| Risk preservation | Existing sizing/guards/execution untouched; new preflight and controlled rejection tests | No live account/broker validation or claim that modeled stops guarantee losses |
| Reproducible comparison | Five fixed arms and base/stress cases; four registered FX instruments using a matched EURUSD profile; seven eligible 180-day test windows across three instruments; complete archived ledgers | Reused development data; three test windows unavailable under unchanged gap checks; reset-fold accounts, not deployed per-instrument profiles |
| Audited correctness | Controlled contract tests plus independent raw-candle, gate, score and monetary audits | Correctness does not establish strategy profitability |
| ML | Optional unavailable/shadow observer, chronological label contracts and ledger invariance | No fitted/calibrated model or measured predictive improvement |
| Dashboard | Existing architecture extended with optional observations and comparison summaries | Observation-only; not an activation or order interface |
| Portfolio/performance | Pure exposure/correlation services tested | No synchronized multi-symbol account replay, marked equity or adequate untouched holdout |

The audit sequence fixed concrete implementation mismatches; it was not a search for settings that force trades. The earlier short scoring study had three scoring-only training positions and no test positions. The subsequent preregistered broader study kept the exact same signal implementation, thresholds, costs and risk settings. Full adaptive produced one test position (-2.86 after costs) under base costs, and none under doubled costs. Other eligible test windows held cash. Isolated positive scoring-only results do not establish full-adaptive performance. No confidence, leverage or position-risk increase is justified.

The broader study used saved histories spanning more than two years for EURUSD, GBPUSD and USDCHF, plus shorter NZDUSD history. The unchanged three-day coverage rule excluded NZDUSD's test and the final EURUSD/GBPUSD tests because of a 72-hour, 6-minute Easter-period bar separation. No window was substituted or guard relaxed. Independent audits passed for 7,519 trade rows across 270 completed ledgers and all 54 full/shadow pairs. Source and production configuration remained unchanged. Broader history has therefore been evaluated, but adequate full-adaptive participation, a genuinely untouched later holdout and synchronized portfolio accounting are still missing.

The engineering foundation supports objective experiments, while the empirical trading objective remains unproven. Any future calibration belongs in chronological training/validation with a separate untouched test; these repeatedly researched histories cannot become a fresh holdout. Relaxing gates merely to produce entries would be a new strategy hypothesis, not another correctness repair.

All adaptive features remain disabled. Existing strategies and production settings are preserved, and no live trades were placed. Latest concrete evidence is in [broader validation results](17_broader_validation_results.md) and its [preregistration](16_broader_validation_preregistration.md); all prior frozen artifacts remain available.
